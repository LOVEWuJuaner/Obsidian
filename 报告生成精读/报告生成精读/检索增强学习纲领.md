**Retrieval-Augmented Medical Report Generation（检索增强医学报告生成）不是一个空白方向，而是 2024-2026 明显升温的方向。**

但是目前还没有像 R2Gen 那样形成一个“统一范式”，这反而说明有机会。

现在这个方向大概分成三条路线：

1. **检索相似病例（Case Retrieval）**
    
2. **检索医学知识（Knowledge Retrieval）**
    
3. **检索增强医学VLM/LLM（Multimodal RAG）**
    

其中第1条最适合你基于 R2Gen 做第一篇论文。

---

# 1. FactMM-RAG（NAACL 2025）——目前最接近你的想法

论文：

**Fact-Aware Multimodal Retrieval Augmentation for Accurate Medical Radiology Report Generation**

NAACL 2025

这是目前我认为与你方向最相关的一篇。([ACL 学会文集](https://aclanthology.org/2025.naacl-long.28/?utm_source=chatgpt.com "Fact-Aware Multimodal Retrieval Augmentation for Accurate Medical Radiology Report Generation - ACL Anthology"))

## 它解决的问题

作者认为：

现在医学报告生成最大问题不是语言流畅性，而是：

> factual inaccuracy（事实错误）

例如：

真实：

```
No pleural effusion.
```

模型：

```
Small pleural effusion is present.
```

所以他们提出：

不要随机检索报告。

而是：

检索：

**事实相关的参考报告。**

---

## 方法结构

大概：

```
Radiology Image

       |
       |
Multimodal Retriever

       |
       |
Similar factual reports

       |
       |
Medical VLM

       |
       |
Generated Report
```

([ACL 学会文集](https://aclanthology.org/2025.naacl-long.28/?utm_source=chatgpt.com "Fact-Aware Multimodal Retrieval Augmentation for Accurate Medical Radiology Report Generation - ACL Anthology"))

---

## 它的创新点

### ① Fact-aware Retriever

普通retrieval：

看图片相似度：

```
image similarity
```

例如：

两张肺部很像。

但是：

医学意义可能不同。

它加入：

RadGraph抽取医学事实：

例如：

实体：

```
pleural effusion
opacity
cardiomegaly
```

关系：

```
finding-location
finding-status
```

让retriever学习：

医学事实相似。

([ACL 学会文集](https://aclanthology.org/2025.naacl-long.28/?utm_source=chatgpt.com "Fact-Aware Multimodal Retrieval Augmentation for Accurate Medical Radiology Report Generation - ACL Anthology"))

---

### ② Retrieval不是辅助语言，而是辅助事实

这是非常重要的思想。

普通RAG：

```
找资料
↓
生成
```

它：

```
找医学事实
↓
约束生成
```

---

## 实验效果

作者报告：

在两个benchmark数据集上：

- 语言指标提升
    
- 医学指标提升
    

尤其：

F1CheXbert最高提升约6.5%

F1RadGraph提升约2%

([ACL 学会文集](https://aclanthology.org/2025.naacl-long.28/?utm_source=chatgpt.com "Fact-Aware Multimodal Retrieval Augmentation for Accurate Medical Radiology Report Generation - ACL Anthology"))

## 它认为：

LLM已经有知识。

但是：

医学报告需要：

额外外部知识。

所以：

不是：

```
LLM
+
全部知识库
```

而是：

```
LLM已有知识

+

检索补充知识
```

融合。

([ACL 学会文集](https://aclanthology.org/2025.acl-long.1279/?utm_source=chatgpt.com "RADAR: Enhancing Radiology Report Generation with Supplementary Knowledge Injection - ACL Anthology"))

---

## 对你的启发

它提醒一个重要问题：

### Retrieval不是越多越好。

如果你：

top-k=20病例

全部塞进去。

可能：

反而污染。

---

你的模型需要：

retrieval selection。

例如：

```
Top20 retrieved cases

        |
    reranker

        |
    Top3 useful cases

        |
    decoder
```

# 问题2：怎么融合？

这是最大的研究空间。

现在很多方法：

简单：

例如：

```
image token

+

retrieved report token
```

然后decoder。

问题：

---

你可以研究：

## Retrieval-guided Cross Attention

原R2Gen：

Decoder:

```
Q=text

K,V=image
```

改：

```
Q=text

K,V=image + retrieved memory
```

---

甚至：

动态门控：

[  
Fusion=\alpha Image+(1-\alpha)Retrieval  
]

# 问题3：检索和生成没有联合优化

先检索。

再生成。

但是：

两个目标不一致。

---

未来方向：

joint training。

例如：

↓

反馈retriever。
